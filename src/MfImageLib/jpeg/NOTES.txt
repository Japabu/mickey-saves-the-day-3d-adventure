IJG libjpeg 6b in MfImageLib.dll -- notes for the libjpeg units
=================================================================

Summary
-------
MfImageLib.dll statically links an UNMODIFIED IJG libjpeg 6b ("6b 27-Mar-1998",
JPEG_LIB_VERSION 62, JMSG_LASTMSGCODE 123), compiled with VC5 /O2 (/Gy) and the
stock jconfig.vc.  The headers in this directory are the pristine 6b files
(jconfig.h = jconfig.vc, byte for byte).  Do not edit them.

Pristine 6b sources: `git clone --depth 1 --branch jpeg-6b
https://github.com/libjpeg-turbo/ijg` (the IJG release history; www.ijg.org is
blocked by the proxy, anonymous git reads of public GitHub repos work).

Measured: compiling every stock 6b .c file and matching every libjpeg function of
the binary (the names in the unit list), 284 of 297 functions MATCH with the
unmodified source.  So the unit work is mostly: copy the stock .c file, rewrite
the includes, add the `/* 0x<va> <name> */` lines, run match.sh per function.

Compiler options
----------------
  /O2 /Gy             for every libjpeg file
  /O2 /Gy /DUSE_WINDOWS_MESSAGEBOX   for jerror.c only

- /O2 alone gives the same bytes; /Gy is used because the linker folded identical
  functions across objects (ICF needs COMDAT functions, i.e. /Gy objects).
- /Ox, /G5, /Op: no improvement on the remaining diffs (see below).
- USE_WINDOWS_MESSAGEBOX: jerror.c tests it (`#ifdef USE_WINDOWS_MESSAGEBOX`
  -> `#include <windows.h>`, output_message calls MessageBoxA(GetActiveWindow(),
  buffer, "JPEG Library Error", MB_OK|MB_ICONERROR)).  Stock jconfig.vc does NOT
  define it and IJG documents it as a compiler switch, so it is a compile define
  on jerror.c's manifest line, not a change to jconfig.h.  Verified:
  output_message (0x100044b0) MATCHES with it, differs without it.

How to include the headers
--------------------------
The .c files live in src/MfImageLib/<file>.c, the headers here in
src/MfImageLib/jpeg/.  Rewrite each stock `#include "jXXX.h"` to
`#include "jpeg/jXXX.h"` (headers including each other, e.g. jinclude.h ->
jconfig.h, jpeglib.h -> jmorecfg.h/jpegint.h/jerror.h, work because cl searches
the including header's directory first).  One-liner used:
  sed -e 's/#include "j\([a-z]*\)\.h"/#include "jpeg\/j\1.h"/' jXXX.c
Keep everything else as in 6b, in particular `#define JPEG_INTERNALS` before the
includes (all library files have it), and the per-file extras:
  jmemmgr.c, jmemnobs.c    + jpeg/jmemsys.h  (jmemmgr.c also #define AM_MEMORY_MANAGER)
  jchuff.c, jcphuff.c      + jpeg/jchuff.h
  jdhuff.c, jdphuff.c      + jpeg/jdhuff.h
  jcdctmgr.c, jddctmgr.c, jfdct*.c, jidct*.c   + jpeg/jdct.h
  jerror.c                 + jpeg/jversion.h, jpeg/jerror.h (with JMESSAGE table)
  jdmerge.c, jdcolor.c, jccolor.c, jquant*.c: stock (defines in the .c file)
Each function needs `--sym _<name>` on match.sh / manifest lines (C names, static
functions included: `--sym _examine_app0`).

Pitfalls
--------
- Identical-code folding (ICF): several functions exist once in the binary but
  in several sources.  0x1000b750 (a lone `ret`) is jcsample
  start_pass_downsample and also jdatasrc term_source, jccolor null_method,
  jdcolor start_pass_dcolor, jquant1 finish_pass_1_quant, jquant2
  finish_pass2 (and possibly jcmarker); jpeg_destroy_compress is folded into
  0x10003ce0 jpeg_destroy_decompress; jmemnobs get/free small/large.  Keep the
  function in every source file (source order), and add a manifest line for it
  in each unit with the folded VA and its own --sym (as in jmemnobs.txt).
- Object order in the binary: each object's functions in source order, but a
  static function is emitted right after its first user (so the address order
  differs from the 6b file order; keep the 6b file order in the .c file).
- Static functions are matched with `--sym _name` like globals.
- boolean is unsigned char (jconfig.vc); byte-sized flags in the structs.
- Do not define NEED_FAR_POINTERS etc.: jutils jcopy_block_row/jzero_far use
  the MEMCOPY/MEMZERO (memcpy/memset) path and match that way.
- jmemmgr reads getenv("JPEGMEM") (NO_GETENV not defined), as stock.
